# Release 4.5.0

A quicker, richer inspection: a quick mode, frame counts, several disease signs, and the queen noted from the same form.
Two update hooks (`hivelog_update_10042`, `hivelog_update_10043`). **Breaking for the field app:** the v1
`disease_signs` attribute is now a list. Covers every change on `main` since the 4.4.1 tag.

## Changes
- **Quick inspection (task 0279).** `Quick Inspection` on the hive page opens the add form with `?mode=quick`: one flat
  form with date, queen seen, eggs seen, honey stores, population, temperament and notes, plus the Queen observation and
  Next visit sections. Honey stores and population start from the hive's last inspection; nothing else is carried over,
  because a stale "yes" would be a false record. It saves the same inspection as the full form, which stays the default,
  and each form links to the other.
- **Frames of bees and brood (task 0279).** Two optional counts (0 to 40) beside Population, shown as tiles, for comparing a
  colony between visits.
- **Several disease signs (task 0279).** Disease signs are checkboxes; tick every one seen. None cannot be combined with
  another sign (the API refuses it too). A serious sign (AFB or EFB) anywhere in the list is critical; the tile lists
  every sign.
- **The queen, noted from the inspection (tasks 0294, 0295, ADR-0111).** A new inspection of a hive with an active queen
  offers a Queen observation section (health, actively laying), saved as a queen observation in the same save. Temperament
  is recorded per visit and the hive's and queen's temperament follow the latest record.
- **Clearer help (task 0296).** Help text and short hints say when an inspection and a queen observation each apply.
- **Lint at zero (task 0289).** `composer lint` reports no errors and no warnings.
- **Housekeeping.** The demo kit stays out of module discovery with a per-site setting (task 0235, documented); the
  seasonal calendar umbrella task 0026 is closed.

## Upgrade notes
- Run `drush updb`, then `drush cr`. `hivelog_update_10042` adds the two frame fields. `hivelog_update_10043` moves
  `disease_signs` into a table of its own, one row per old value, without touching `changed`.
- **Field app (v1, changed in place).** `disease_signs` is an array of strings, for example `["nosema","chalkbrood"]`, and
  `["none"]` stands alone. The Vinculum app was unreleased, so the version is unchanged. `frames_of_bees` and
  `frames_of_brood` are new optional integer attributes.
- A site that reads `disease_signs` as a single value in a theme, view or integration needs to read the list.
- No new permissions.

## Known limitations
- The new frame fields are not in `collective`'s minimised context payload.
- Quick mode was verified in kernel tests, not yet in a browser.
- The disease-signs migration has no automated test; it was run once on a local copy of the hvg data.
