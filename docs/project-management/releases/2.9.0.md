# Release 2.9.0

Adds sign-out to the optional `hivelog_api` submodule and names the OAuth client
after the iOS app, Vinculum (task 0204). Nothing changes unless you have enabled
`hivelog_api`.

## Highlights
- **New: `POST /hivelog/api/v1/sign-out`.** simple_oauth 6 has no revocation
  endpoint, so an app could not truly sign a user out. This revokes the bearer
  token's access token and, if the body carries `{"refresh_token": "..."}`, that
  refresh token too, so one device signs out and the user's other devices stay
  signed in. The refresh token is only honoured if it belongs to the same user and
  client as the bearer. It answers 204; a session user (no token) gets a 400. The
  discovery document advertises it as `meta.hivelog_api.oauth.sign_out`.
- **The consent screen now says "Vinculum".** The OAuth client's label and the
  scope wording named the "HiveLog field app". `hivelog_api_update_10001()` renames
  them on existing sites, and only where they still have the old default, so a
  label an administrator chose is left alone.
- **Fix: enabling `hivelog_api` together with simple_oauth could fail** with
  "Table `consumer__grant_types` doesn't exist". Found by enabling the module on a
  real dev site: the consumer entity's extra fields had not been created when the
  client was. Install now creates any that are missing first.

## Schema / update hooks
- `hivelog_api_update_10001()`: renames the default OAuth client label and scope
  wording to Vinculum. No schema change.

## Upgrade notes
- **Only affects a site that has enabled `hivelog_api`.** Core HiveLog is unchanged.
- Run `drush updb` (one update hook) and `drush cr`.
- Sites that already show "HiveLog field app" on the consent screen will show
  "Vinculum" after the update.
