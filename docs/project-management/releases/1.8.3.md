# Release 1.8.3

## Highlights
- **Module themeability — surface colour tokens.** The dashboard,
  "needs attention" queue, stat tiles, the upcoming/recent split and the
  financial-report tables had their colours hard-coded as hex, so a site
  theme (beeswax, task 0061) had to restate the module's own selectors
  just to recolour them. Those colours are now a `--hivelog-*` token
  surface on `:root` in `css/hivelog.responsive.css` —
  `--hivelog-surface`, `-surface-2`, `-ground`, `-ink`, `-ink-muted`,
  `-ink-faint`, `-hairline`, `-border`, `-rule`, `-critical` /
  `-critical-tint`, `-warning` / `-warning-tint` — consumed by
  `hivelog.dashboard.css`, `hivelog.tables.css`, `hivelog.filter-form.css`,
  `hivelog.forms.css` and the `stat-tile` / `entity-table` SDC sheets.
  A theme recolours HiveLog by redefining ~a dozen properties instead of
  duplicating rules. Stock values are unchanged bar five sub-perceptual
  consolidations of near-duplicate greys / one red (1px rules and small
  text) — documented in the `:root` comment.
- **`hivelog-page` body class.** New `hivelog_preprocess_html()` adds a
  `hivelog-page` class to `<body>` on every route whose path is under
  `/hivelog` (path match — the plain `entity.<type>.collection` routes
  are not named `hivelog.*`, the same gap `HivelogBreadcrumbBuilder`
  handles). A skin theme can scope whole-page rules to
  `body.hivelog-page` without its own `preprocess_html`.
- **Theming contract documented.** New "Theming HiveLog" section in
  `AGENTS.md`: the token lists, the stable `.hivelog-*` class names, and
  the "attach the skin from the theme's `global` library, not
  `libraries-extend`" seam.
