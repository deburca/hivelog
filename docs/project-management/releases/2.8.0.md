# Release 2.8.0

## Highlights
- **The HiveLog API now serves the values no record stores (task 0202).** Three
  read-only endpoints under `/hivelog/api/v1/computed/`, for the field app and any
  other client of the optional `hivelog_api` submodule:
  - **`alerts`** is the dashboard's "Needs attention" queue for the signed-in user,
    including overdue and due seasonal tasks, low stock, and whatever `nanoprobe`
    (device offline, possible swarm, temperature) and `nexus` (stale AI provider)
    raise. Each row names its apiary, hive and calendar action, so a client can
    report a task done through the JSON:API.
  - **`hive/{hive}/stat-tiles`** is the hive page's "at a glance" tiles, plus the
    hive's empty weight so a client can show net weight.
  - **`hive/{hive}/insight`** is the latest AI insight for the hive, as data.
  Hives are addressed by UUID, the id a client already has. A hive you cannot see
  is a 403, an unknown one a 404, and no credentials a 401. They work with the same
  OAuth token as the rest of the API.
- **One implementation behind the website and the API.** The dashboard's alert
  collection moved into a shared service (`hivelog.alert_collector`), and the stat
  tile builder gained a data-only method, so the app cannot disagree with the
  website. Alert rows now carry optional `kind` and `subject` data fields; a custom
  `hook_hivelog_needs_attention_alerts()` implementation should set them (rows
  without them still show on the dashboard and are served by the API without an
  apiary or hive).
- **New hook `hook_hivelog_api_hive_insight()`** (in `hivelog_api.api.php`),
  implemented by `nexus`, so the API never depends on `nexus`.

## Schema / update hooks
None. No entity schema, field definition or permission changed.

## Upgrade notes
- **No change to the website.** The dashboard looks and behaves as before; the
  refactor is internal, and the 68 existing dashboard, tile and alert tests passed
  unchanged.
- The new endpoints exist only on a site that has enabled `hivelog_api`.
- A custom module that overrode or extended `DashboardController`'s protected alert
  methods (`collectSeasonalAlerts()` and the like) will find them moved to
  `HivelogAlertCollector`. Nothing in HiveLog itself does.
- Run `drush cr` after upgrading so the new service and routes are picked up.
