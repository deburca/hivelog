# Release 2.3.0

## Highlights
- **Filters on the Hive and Apiary Action Log lists (task 0168).**
  `/hivelog/hive-action-logs` and `/hivelog/apiary-action-logs` were the
  last full collection pages without a filter form — they were never named
  in the scope of collection-page-filter-coverage, so they stayed
  unfiltered when it closed. Each now filters by:
  - **Status** (pending / done / ignored), taken from the entity definition;
  - **Year** (digits only — anything else is ignored rather than passed to
    the query);
  - **Calendar action contains** and **Hive contains** / **Apiary contains**,
    as text matches. These are deliberately not dropdowns: a select would
    list every calendar action, hive or apiary on the site to a user who
    may only be allowed to see some of them, whereas a text match only
    narrows rows the list has already access-filtered per row. The cost is
    no dropdown convenience, and a log whose hive or action has since been
    deleted can't be found by name.
  - Filter state lives in the query string, Reset returns to the bare
    collection, the empty state distinguishes "no logs yet" from "none match
    your filters", and pager links keep the active filter.
  - Built as one shared `HivelogActionLogFilterFormBase` with two thin
    subclasses, since the two log types have identical fields.
- **Docs.** AGENTS.md now documents the filter-hook pattern
  (`getFilterForm()` / `applyFilters()` / `hasActiveFilters()`, GET forms with
  static `extract()` / `apply()`, the `filter_actions` container name that
  keeps Gin from hoisting the buttons, and the text-over-select rule for
  related-entity filters), which it didn't describe before.
