# Release 2.2.0

## Highlights
- **Hive component weight tracking (ADR-0106, tasks 0162-0164).** A hive's
  own tare (empty) weight can now be composed and computed instead of
  guessed:
  - `InventoryItem` gains an optional `weight_kg` field (task 0162) — a
    catalog entry (brood box, base plate, roof, …) can now declare its own
    per-unit weight alongside its existing cost/stock fields.
  - A new `HiveComponent` entity (task 0163) lets a hive declare its own
    composition — which catalog items, how many of each — mirroring
    `CalendarActionItemRequirement`'s existing "recipe" shape. Two guards
    enforce it can never drift from reality: same-apiary (a hive can only
    be built from its own apiary's catalog) and a stock-availability
    ceiling (a component can never be assigned past how many units of
    that item are actually in inventory, computed live from purchases
    minus every other hive's own assignments — never a stored running
    balance). A new `Hive::getEmptyWeightKg()` sums the hive's components,
    returning `NULL` — not a partial, misleadingly-precise number — the
    moment any referenced item has no `weight_kg` set, so an incomplete
    composition never silently understates the hive's real tare weight.
    An embedded "Hive Components" section on the Hive canonical page adds,
    edits and removes rows, with a live per-item "(N available)" hint in
    the item picker.
  - `nanoprobe`'s Sensors panel gains a `Net Colony Weight` stat tile
    (task 0164) alongside its existing per-device tiles: a hive's latest
    raw `weight_kg` sensor reading minus `getEmptyWeightKg()` — the figure
    a beekeeper actually cares about, not just total weight on the scale.
    An incomplete composition doesn't hide the tile; it shows a "Hive
    composition incomplete" warning linking straight to the Hive
    Components section instead.
  - This is the first software-side payoff of the pilot weight-sensor
    hardware (task 0079, procurement arrived this same period) — the
    tile is ready for real readings the moment a physical sensor reports.
- **Hardware fix (task 0079).** Fixed a genuine compile bug in the
  `oneof9`/receiver firmware — a missing `#include <map>` — found while
  reviewing the firmware ahead of flashing the newly-arrived pilot
  hardware. Firmware/hardware work itself remains `in-progress`
  (procurement, not full deployment) and is not otherwise part of this
  release.

## Schema / update hooks
Two new update hooks, both idempotent and re-run-safe per the module's own
convention (`\Drupal::entityDefinitionUpdateManager()`, no destructive
`drush entity:updates`):
- `hivelog_update_10030` — installs the new `weight_kg` field storage on
  `InventoryItem` (task 0162).
- `hivelog_update_10031` — installs the new `hive_component` entity type
  (task 0163).

No update hook for task 0164 — it adds no schema, only a new computed stat
tile.

## Upgrade notes
- No breaking changes, no destructive migration.
- Run `ddev drush updb -y && ddev drush cr` after upgrading to pick up the
  two new update hooks above.
- Seven new permissions ship for `hive_component` (view own/any, add, edit
  own/any, delete own/any) — grant them to any role that should be able to
  compose a hive's weight, same as every other entity type's own
  view/add/edit/delete permission set.
- A hive with no `HiveComponent` rows yet behaves exactly as before
  (`getEmptyWeightKg()` returns `NULL`, no net-weight tile renders beyond
  the existing per-device ones) — nothing regresses for a site that
  doesn't use this feature yet.
