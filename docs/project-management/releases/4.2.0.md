# Release 4.2.0

Minor release. No schema change; one update hook that grants permissions.

## Changes
- **Choose or copy an apiary's calendar (task 0249).** A new apiary can start from the built-in calendar or a copy of
  another apiary's (the Details tab's "Seasonal calendar" select, shown only when the user has other apiaries to copy
  from), and an existing apiary gets **Copy a calendar** on its Calendar page. Copying is additive and repeatable
  (an action with the same title, scope and starting week is skipped; nothing is deleted), carries the item
  requirements and product yields, matching them to the target's catalogue by name and unit and creating them there if
  missing (catalogue data only, no purchases). Sources are limited to apiaries the user may view. A regional preset is
  one more source in `HivelogCalendarCopier`, with no caller changes.
- **The field app can add and edit hives and queens (task 0027).** The `hivelog_field_app` role now holds `add hive`,
  `add queen` and `edit own hive|queen`, so Vinculum can set up hives and manage queens in the field. It still cannot
  create an apiary or a calendar action, and its delete ceiling is unchanged (only its own inspections and queen
  observations).
- **A second active queen demotes the first through the API too**, as on the web (`Queen::preSave()`). The API does not
  refuse it.

## Upgrade notes
- Run `drush updb`: `hivelog_api_update_10006()` adds the four permissions to the field-app role. It is additive and
  never revokes a permission a site has changed. Then `drush cr`.
- A site that wants to keep the app unable to create hives and queens can remove those permissions from the
  `hivelog_field_app` role after updating.
