# Release 2.8.1

A hardening and bug-fix release for the optional `hivelog_api` submodule
(task 0203). Nothing changes unless you have enabled it.

## Highlights
- **The API is now tested against the web UI's own access rules.** For every
  exposed record type, an owner, an unrelated beekeeper, a beekeeper member of the
  apiary, a "view any" user and an administrator are each compared, for read, list,
  update, create and delete, against what the website itself allows. The API
  matched everywhere, and a refusal is never a server error.
- **Fix: collections could come back empty, and named other people's records.**
  JSON:API paginates before it checks who may see a record, so a collection's first
  page was the first 50 records on the site whoever owned them. A user whose
  records came later got an empty page (the calendar action list was empty for its
  own owner), and the response listed the ids and addresses of the records it had
  dropped. Collections are now narrowed to the records the user may view before
  they are paged, so pages are full and nothing is named as omitted.
- **Fix: no credentials is now a 401, not a 403 or an empty list.** A request with
  no token on `/hivelog/api/v1` (other than the public discovery document) gets a
  401 with a `WWW-Authenticate: Bearer` header, as JSON. A missing, invalid or
  expired token now all mean the same thing to a client: refresh or sign in.
- **The file collection is no longer served.** `/hivelog/api/v1/file/file` would
  have listed every file on the site; a file is still fetched by id, and uploaded
  onto a field, as before.
- **Proven hidden:** with every optional submodule enabled, inventory, products,
  components, sensors, API clients, AI providers and insights exist in plain
  JSON:API but return 404 on the versioned API; and a rule broken through the API
  (feed type, varroa count, week range, an action from another apiary, missing
  fields, bad values) is a 422 naming the field.

## Upgrade notes
- **Only affects a site that has enabled `hivelog_api`.** Core HiveLog is unchanged.
- A client that treated a 403 or an empty collection as "not signed in" should now
  expect a 401. The 14-day refresh-token lifetime (simple_oauth's default, set per
  client) is how long a device can be offline before the user must sign in again.
- A collection costs a PHP access check per record of that type per request, the
  same way the web lists work. Fine at beekeeping scale.
- Run `drush cr` after upgrading.
