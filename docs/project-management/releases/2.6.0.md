# Release 2.6.0

## Highlights
- **Validation rules now live on the entities, not only in forms (task 0200).**
  Twelve data-integrity rules that were enforced only by a form's
  `validateForm()` (with a `preSave()` throw behind it) are now entity
  constraints: same-apiary for hive components, requirements, yields and
  purchases; component quantity not above what is available; a durable item
  needs a useful life; disposal date rules on purchases; a calendar action's
  end week not before its start; the inspection feed-type and varroa-count
  rules; a sensor device's hive matching its scope; and an AI provider's
  key/provider/endpoint by mode. Forms show exactly the same messages as
  before, and now any other caller (a script, an import, a future API) gets
  a validation error from `$entity->validate()` instead of a 500 from
  `preSave()`. `preSave()` keeps its throw as the backstop.
- **A record can no longer be created under, or moved into, someone else's
  apiary or hive by a caller that skips the web routes.** A new parent-access
  constraint applies the scoped add routes' rule (you must be able to update
  the parent) to every child type. The web UI was already safe; this closes the
  gap a generic API would have opened (found in spike 0198).
- **A log's calendar action must belong to the log's apiary.** Nothing enforced
  this before. Existing rows are not re-validated.

## Docs (no code)
Spike 0198 (stock JSON:API plus `simple_oauth` against HiveLog's access rules)
and the offline decision 0199 (an outbox for writes plus a read cache), with
ADR-0107 now `accepted`. They describe the planned mobile API and change nothing
in the module.

## Upgrade notes
- No data migration. Run `ddev drush cr` after upgrading so the new constraint
  plugins are discovered.
- **Behaviour change for code that calls `$entity->validate()`**: it now also
  checks the parent-access rule against the *current user*. A script or cron job
  that validates as an anonymous or low-privilege user, then saves a child of
  an apiary or hive that user cannot update, will now get a violation. Run such
  code as a user with access, or skip `validate()` (as before, `save()` does not
  call it).
- A custom form that extends a HiveLog form and relied on its `validateForm()`
  rules should drop its own copy; the rule now runs in
  `ContentEntityForm::validateForm()`.
