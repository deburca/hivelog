# Release 1.8.8

## Highlights
- **Two SQLite-only Kernel test failures fixed (PR #139).** Investigated two
  kernel tests that failed when run against a local SQLite database — not
  test-order-dependent flakiness as initially suspected, but two genuine
  bugs that CI's MySQL-only test matrix never surfaced:
  - `ApiaryController::applyFullCalendarFilters()` bound a raw PHP `bool`
    into the `enabled` entity query condition. PDO's SQLite driver casts an
    unbound `FALSE` to the empty string, which never matches an integer
    column, so the Full Calendar's `enabled=0` filter silently returned
    zero rows on SQLite. Fixed by binding an explicit `1`/`0`.
  - `QueenTest::testCreateQueen` asserted decimal field storage returns the
    exact string `'35.50'`. SQLite's NUMERIC-affinity typing drops the
    trailing zero (`'35.5'`), unlike MySQL/PostgreSQL's fixed-precision
    `DECIMAL`. Fixed by comparing the value numerically instead.
- **Pre-existing CI breakage on `main` also fixed in the same PR**, found
  while chasing the above: the `Lint` job had been failing since commit
  `3873032` (2026-09-21) on an unused `SensorReading` import in
  `modules/nanoprobe/src/SensorAlertCollector.php`, and — once lint was
  green again — every `nexus` Kernel test class failed with `Unavailable
  module: 'key'`, because `nexus.info.yml` depends on the `key:key` Drupal
  module but `composer.json` never required `drupal/key`. Both fixed;
  masked locally because the cms2 dev site happened to already have
  `drupal/key` installed for unrelated reasons.

## Included work
- **PR [#139](https://github.com/deburca/hivelog/pull/139)** — fix(hivelog):
