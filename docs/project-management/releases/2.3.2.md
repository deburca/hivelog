# Release 2.3.2

## Highlights
- **Fix: Queen section buttons on the hive page.** Edit Queen and View all
  Queens were separate flex children of the section's heading row, each with
  its own `margin-left: auto`, so the free space was split between them and
  Edit Queen floated mid-row, ungrouped. The heading row now holds the title
  and one right-aligned button group (Add Queen + View all Queens on a hive
  with no active queen), and the details table sits below it.
- **Fix: buttons inside a group in a heading row were spaced apart.** A CSS
  rule meant only for standalone buttons also matched buttons inside a
  `hivelog-button-group` that sat in a heading, leaving a ~7px gap between
  the segments and a gap before the right edge. It is now scoped to buttons
  outside a group. **This is not limited to the hive page:** any list
  heading with a multi-button group is now joined as a single control, which
  is what the group is documented to look like.
- **Accessibility of the in-app nav strip (task 0166).** The strip was a bare
  `div`; it is now a labelled `role="navigation"` landmark, and each hub's
  submenu is a `role="group"` named by its hub link. A 2px gap that closed
  the dropdown under a crossing pointer is bridged (WCAG 1.4.13
  "hoverable"), and the dropdown's transition is disabled under
  `prefers-reduced-motion`. Deliberately **no** `aria-haspopup`,
  `aria-expanded` or `role="menu"` — they promise behaviour a CSS-only
  disclosure can't deliver truthfully (recorded as an amendment to
  ADR-0104, with a guard test).
- **Tests (task 0170).** 16 new tests: filter pagination over the filtered
  set on every full list page, the empty-filtered state on five lists, and
  the Insights hub's active-child cascade. No product code.

## Known gaps
- **No Escape-to-dismiss on the nav dropdown** (WCAG 1.4.13 "dismissible").
  Not possible in CSS; it needs a small script and a decision on ADR-0104's
  "no JavaScript" position. Open.
- **Not checked with a screen reader** or an accessibility-tree read of the
  live page; the nav announcements are inferred from the markup.

## Upgrade notes
- No breaking changes, no data migration.
- `ddev drush cr` after upgrading so aggregated CSS is rebuilt.
- A theme that overrides `css/hivelog.buttons.css` should pick up the
  `:not(.hivelog-button-group .button)` on the standalone-button
  right-margin rule, or grouped buttons in headings will keep their gap.
- The Queen section's render array changed: the loose `edit`, `add` and
  `view_all` button children are gone, replaced by `heading.actions.buttons`.
  A site altering the hive page's render array by those keys would need to
  follow.
