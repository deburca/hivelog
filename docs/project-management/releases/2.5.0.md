# Release 2.5.0

## Highlights
- **Calendar Actions, the action logs and the financial report are now
  discoverable (task 0172).** An audit of how a beekeeper reaches each of
  them found one real gap: the site-wide **Calendar Actions** list was
  reachable only from the dashboard's "Open seasonal tasks" tile.
  - **Calendar Actions is a navigation item**, under Apiaries, with the
    breadcrumb `Home › Apiaries › Calendar Actions` (the same shape as Hives).
    It also gets a derived main-menu link. This adds a leaf under an existing
    hub; the hierarchy is unchanged (ADR-0104 amendment).
  - **The Hive and Apiary Action Log lists are deliberately not nav items**:
    the Apiaries submenu would reach ten entries, and the logs are an audit
    trail read alongside the calendar. They previously had no heading at all;
    now Calendar Actions links to both logs, and each log list links back to
    Calendar Actions and to its sibling list.
  - **Inventory Purchases now links to the financial report**, beside
    Products.
  - **The per-apiary Full Calendar and cost report are unchanged**: they need
    a chosen apiary, so they stay reached from the apiary and hive pages.
- **Fix: a link that led to a 403.** The Products page's "View Financial
  Report" button (added in 2.1.0) was shown to anyone who could see Products,
  but the report needs inventory-item view access, a different permission. All
  these cross-links now come from one helper that offers a link only if the
  target route's own access check passes, and the heading varies by
  permissions in the page cache so one viewer's buttons can't be served to
  another.

## Upgrade notes
- No breaking changes, no data migration.
- **Run `ddev drush cr` after upgrading** so the new Calendar Actions
  main-menu link, which comes from plugin discovery, is picked up. A site that
  has re-weighted or disabled hivelog menu links in the menu UI will see the
  new link at its default position.
- A custom `HivelogListBuilder` subclass is unaffected; to add permission-gated
  heading links, use `HivelogListPageTrait::accessibleLinkAction()` (valid for
  permission-gated routes; an entity-access-gated target needs the `user`
  cache context instead).
