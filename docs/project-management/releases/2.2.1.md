# Release 2.2.1

## Highlights
- **Fix: Weight field placement on the Inventory Item edit form.** `weight_kg`
  (task 0162, shipped in 2.2.0) was never added to `InventoryItemForm`'s own
  Overview vertical-tab field list, so the widget rendered outside every
  tab entirely — above the "Inventory item details" tabs, instead of
  alongside Unit/Low Stock Threshold/Status where it belongs. Adding it to
  the tab's field list alone wasn't sufficient either: within a tab,
  fields are still ordered by their own base-field display weight, and
  `weight_kg`'s weight (7) sorted it after Low Stock Threshold's (6).
  Fixed by grouping it into the Overview tab and swapping the two fields'
  **form** display weights only (their `view` weights are untouched — the
  canonical page's own explicit per-section field-name arrays order that
  display, not weight). The field now sits directly under Unit, ahead of
  Low Stock Threshold, matching the order the canonical view page already
  used.

## Target tasks
None — an ad hoc fix, no task doc (see commit `c496b8a`).

## Schema / update hooks
None. Both changes are in-code display option tweaks (`baseFieldDefinitions()`'s
`setDisplayOptions('form', …)` weight and a form's own `#group` assignment)
— neither is exported config, and neither is entity schema, so no
`hivelog_update_N` hook is needed.

## Upgrade notes
- No breaking changes, no data migration, no manual steps. A simple
  `ddev drush cr` after upgrading is enough to pick up the changed
  in-code display weight (base field display options are cached).
