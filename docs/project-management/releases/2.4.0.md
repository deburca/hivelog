# Release 2.4.0

## Highlights
- **Sortable columns on the full collection lists (task 0171).** Column
  headers on 13 lists become sort links that toggle ascending and
  descending: Apiaries, Hives, Inspections, Queens, Queen Observations,
  Inventory Items, Inventory Purchases, Products, Hive and Apiary Action
  Logs, API Clients, Sensor Devices and AI Provider Configs. Calendar
  Actions is controller-built and unchanged.
  - **Safe by construction.** Each list opts in with `getSortableColumns()`,
    a whitelist mapping a header to what it sorts on. The `sort` query
    parameter is only ever matched against those keys, so nothing a visitor
    sends reaches the query as a field name or path. An unknown or
    unsortable key, an array-valued parameter, or a junk `order` falls back
    to the default order. The default id key stays as the tie-breaker, so
    equal values and NULLs page deterministically.
  - **Correct ordering.** Sorting is in the entity query, so numbers sort as
    numbers (9.5 before 100), not as text.
  - **Related names.** The **Apiary** column (Hives, Inventory Items,
    Purchases, Products, Apiary Action Logs) and **Hive Action Logs'
    Hive** column sort by the related record's name. A record whose apiary
    or hive has since been deleted stays listed (at the NULL end) instead of
    vanishing.
  - **Works with the rest of the list.** A new sort keeps your filters but
    resets the page; the filter form carries the sort through as hidden
    inputs so filtering doesn't silently reset it; pager links keep it;
    Reset clears filters and sort together.
  - **Accessible and responsive.** Sortable headers carry `aria-sort`. On
    phones the header row is normally hidden (the table becomes cards),
    which would have left the links as invisible tab stops, so a sortable
    table shows a compact "Sort by: Hive ▼ Status ⇅" bar instead.
  - **Deliberately not sortable:** computed columns (stock on hand, total
    cost, breed), the remaining reference columns (Hive on Inspections,
    Queen on Observations, Item on Purchases), and ordinal enums whose
    alphabetical order would mislead (health, honey stores, temperament).
    The reference columns would take a one-line entry each if wanted.
- **Component change.** `hivelog:entity-table` gains an optional
  `column_sorts` prop (omitted when empty); existing callers are unaffected.

## Schema / update hooks
None. No entity schema, field definition or permission changed.

## Upgrade notes
- No breaking changes, no data migration.
- `ddev drush cr` after upgrading so the component template and CSS are
  rebuilt.
- A theme overriding `entity-table.twig` or `entity-table.css` will not get
  the sort links or the mobile "Sort by" bar until it adopts them.
- A custom list builder extending `HivelogListBuilder` is unaffected; to opt
  in, override `getSortableColumns()` (header key => stored field, or a
  relationship path such as `apiary.entity.name`).
