# Release 2.1.0

## Highlights
- **Two-tier in-app navigation (ADR-0104, tasks 0146-0151).** The nav strip
  and its mirrored main-menu tree move from one flat row of 11+ destinations
  to two tiers: three primary items (Dashboard, Apiaries, Insights) with
  every other destination nested under whichever one is its logical parent.
  A new "Setup"/Insights landing page (task 0146, renamed by task 0152) gives
  submodule-contributed destinations (API Clients, AI Provider Configs,
  Sensor Devices) a primary item to nest under. CSS-only dropdown/accordion
  disclosure, no JavaScript (task 0149) — corrected same-day after a live
  regression on `/hivelog/hives` where a hub's dropdown force-opened over
  the page content below it; disclosure is `:hover`/`:focus-within` only now.
- **Collection-page breadcrumb ancestry + Insights rename (ADR-0105, tasks
  0152-0154).** Ten collection routes (Hives, Inspections, Queens, Queen
  Observations, Inventory Items, Inventory Purchases, Products, API
  Clients, AI Provider Configs, Sensor Devices) now thread a proper
  ancestor chain in their own breadcrumb (`Apiaries › Hives › Inspections`,
  `Insights › AI Providers`, …) via a new, independent
  `COLLECTION_ANCESTOR_ROUTE` map — separate from the existing per-instance
  `PARENT_FIELD` map canonical/edit/delete pages use, which is unchanged.
  "Setup" is renamed to "Insights" throughout (route, controller, nav item,
  breadcrumbs) — a clean rename, no compatibility shim, since nothing had
  shipped in a tagged release yet.
- **Filters on every remaining collection page (tasks 0155-0158).** The
  filter-form pattern task 0132 established for Hives/Inspections/Queen
  Observations now covers the eight collection pages that still had none:
  Apiaries, Queens, Inventory Items, Inventory Purchases, Products, AI
  Provider Configs, Sensor Devices, and API Clients (added to scope
  mid-stream, task 0158) — eight new `HivelogXFilterForm` classes, each
  wired into its entity's list builder via the shared
  `getFilterForm()`/`applyFilters()`/`hasActiveFilters()` hooks, no changes
  to the shared base class itself.
- **Navigational polish (tasks 0159-0160).** The Hives, Inspections and
  Queen Observations collection pages — which have no Add button by design
  (no context-free add route for any of the three) — now carry a "View
  <parent collection>" cross-link in the same heading slot every other
  filtered list has, instead of no heading at all. The Products page gains
  a "View Financial Report" cross-link to the combined financial report
  (`hivelog.apiaries.financial_report`), which has never had its own
  nav-strip entry (task 0120 excluded it deliberately) and was otherwise
  reachable only from the apiary page's own button and the dashboard's Net
  YTD tile.
- **Hexagon nav button shape (task 0161).** The in-app nav strip's own
  buttons (`.hivelog-app-nav__link`) trade their fully-rounded pill ends
  for an elongated hexagon — flat top/bottom, pointed left/right sides —
  leaning into the honeycomb motif. Scoped to the nav strip only; the
  generic `hivelog:button` component used everywhere else (Edit/Delete/
  Add/View/Filter/Reset) is unaffected.
- **Housekeeping.** Name now sorts before CBR in the Apiaries list table
  (more relevant to that page than the CBR number).

## Schema / update hooks
None. No entity schema, field definition, or permission changed in this
release — every task here is UI/navigation/breadcrumb/filter/CSS work
against existing fields and routes. `drush updatedb-status` is clean.

## Upgrade notes
- No breaking changes, no data migration, no manual steps.
- Any per-site menu-UI customisation of the nav items this release
  re-nests (weight/enabled/expanded) carries forward unchanged — task
  0150 needed no update hook, since a derived plugin ID's *shape* never
  changed, only the `parent` value inside its existing definition.
- If a site customised `css/hivelog.app-nav.css` locally (unlikely, but
  possible via a theme override), the nav-strip buttons' shape changed
  from a rounded pill (`border-radius: 999px`) to a `clip-path` hexagon —
  review any such override.
