# Release 1.8.9

## Highlights
- **Security: list pages no longer leak other users' rows (task 0124).**
  `HivelogListBuilder::load()` now filters every collection page —
  Apiaries, Hives, Inspections, Queens, Queen Observations, both
  action-log lists, inventory items/purchases, products, API Clients,
  AI Provider Configs — by per-row `access('view')`. Previously a user
  with only a "view own X" permission saw every other user's rows in
  the rendered table: core's `EntityListBuilder` query `accessCheck
  (TRUE)` never actually filters an entity type with no `query_access`
  handler, and none of HiveLog's entity types declare one.
- **Security: every route now enforces per-entity access, closing an
  IDOR (task 0133).** Every hivelog/nanoprobe/collective/nexus route
  with an entity parameter previously checked only a coarse
  `_permission` (own/any/admin) — never the entity's own access
  handler. A user with "own" permissions but no relationship to a
  specific apiary/hive/etc. could view, edit or delete it by URL
  (`access_manager::checkNamedRoute()` returned ALLOWED even though
  `$entity->access()` correctly said no). Every route now also carries
  `_entity_access` / `_entity_create_access`, and a new same-apiary
  check stops logging a hive/apiary action against another apiary's
  calendar action by URL.
  - **Behaviour change:** an apiary's own `update` operation is
    owner-only (unlike every child type's member-scoped `update`), so a
    beekeeper member can no longer add new apiary-direct structure (a
    hive, a calendar action, inventory items/purchases, products) to an
    apiary they don't own — only edit what already exists there. This
    tightens, rather than reopens, the gap being closed.
- **Apiary page decluttered (task 0114).** Dropped the read-only "AI
  insights enabled" indicator, the apiary-scoped Sensors panel's "Add
  Sensor" button, and the now-pointless bare "Sensors" heading above it.

## Upgrade notes
- **Security-relevant — update promptly.** Both 0124 and 0133 close
  real information-disclosure / IDOR gaps affecting any multi-tenant
  HiveLog site (more than one apiary owner). No API or schema change;
  the fix is routing and list-builder logic only.
- A beekeeper member (not the apiary owner) can no longer reach
  `hivelog.hive.add`, `.calendar_action.add`, `.apiary_action_log.add`,
  `.inventory_item.add`, `.inventory_purchase.add`, `.product.add`, or
  `entity.apiary.edit_form` for an apiary they don't own — previously
  unenforced at the route level. They can still view and edit every
  existing child entity in an apiary they're a member of.
