# Release 4.0.0

Major release: the field-app API moves to `/api/v1`, and a site can choose the prefix its pages are served under. No
schema change, no update hook.

## Changes
- **Breaking: the API is at `/api/v1`** (was `/hivelog/api/v1`). The version is still 1 and everything under the
  prefix is unchanged: the OAuth endpoints, the discovery document (`GET /api/v1`), the JSON:API resources, the
  computed views, `schema`, `sign-out`. A client must use the new base path; the Vinculum app needs an update.
- **New: `$settings['hivelog_path_prefix']`** serves the pages at `/<prefix>/...` instead of `/hivelog/...`
  (`'app'` gives `hivelog.eu/app`). Unset, nothing changes. Route names, permissions and the link templates are
  unchanged. The sensor ingestion and collective context endpoints under `/hivelog/api/` never move.

## Upgrade notes
- Anything calling `/hivelog/api/v1` (the iOS app, scripts, a firewall allow-list) must move to `/api/v1`.
- Run `drush cr`. If you set a prefix, also update `system.site:page.403` / `page.404` (the friendly error pages) and
  any menu link or stored link to a `/hivelog/...` path.
