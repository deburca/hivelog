# Release 2.12.0

Insights for the Vinculum app (task 0221): a hive's latest insight, and the verdicts that tint the hexagon
badge on each hive in the app, now reach an app token. Only matters on a site that runs the optional
`nexus` module; nothing changes without it.

## Highlights
- **The app could never see a hive's insight.** The `hivelog_field_app` role, which caps what an app
  token can do, had no `view own hive insight` permission, so `computed/hive/{hive}/insight` answered
  "nothing" for every app user and the app never showed an insight (the same gap the sensors had, fixed
  in 2.11.2). The role now holds that one permission: view own only, with no edit, add, delete or "any".
  It is granted only where `nexus` defines it, and topped up automatically if `nexus` is installed after
  `hivelog_api`. `hivelog_api_update_10003()` adds it on an existing site and never revokes a change a
  site made.
- **`GET /hivelog/api/v1/computed/apiary/{apiary}/hive-insights`** answers each viewable hive's latest
  insight verdict (`hive` UUID, `verdict`, `verdict_label`, `stale`, `generated`) in one request, so
  the app can tint every hive's badge in a list without a request per row. It calls the same hook as the
  per-hive endpoint, with the same access rules and the same opt-in (an apiary must have AI insights on), so
  `hivelog_api` still does not depend on `nexus`. A hive with no insight is left out; another
  beekeeper's apiary is a 403. Read-only.
- **The demo kit** (`demo/`, not part of the package) runs `nexus`, seeds three sample insights with no AI
  provider, and `ddev demo-reset` makes the insights and sensor readings current again after a reset.
- CI is much quicker (a full run is about 10 minutes instead of 35, and docs-only pushes run nothing): not
  something a site sees, listed for the record (tasks 0217 and 0218).

## Schema / update hooks
- `hivelog_api_update_10003()`: tops up the field-app role with `view own hive insight` (a no-op without
  `nexus`). No entity schema changes.

## Upgrade notes
- Run `drush updb` (the role update) and `drush cr` (the new route).
- **Who can now see what:** an app token can read the signed-in user's *own* hive insights (through the two
  computed endpoints and through the web routes the user could already open); the access handlers still
  scope "own" to the apiary owner or a beekeeper member, and an apiary must have opted in to AI insights.
  Nothing can be written.
- Only matters if `nexus` is enabled. Without it nothing changes.
- The app shows the tinted badges from the Vinculum build that includes task 0221; an older app simply
  ignores the new endpoint, and a newer app against an older server shows plain badges.
