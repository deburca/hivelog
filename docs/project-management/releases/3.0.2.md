# Release 3.0.2

Patch release for 3.0.1. One update hook, no schema change.

## Changes
- **The app's role is named for what it is for.** The `hivelog_field_app` role, which a person needs to sign in to
  the app, is now labelled **HiveLog mobile app user**. Without the role, sign-in stops with only "The 'grant
  simple_oauth codes' permission is required", found while rolling 3.0.x out to the live site (task 0233). New
  installs get the new label; `hivelog_api_update_10005()` renames the earlier default "HiveLog field app" and
  leaves a label a site chose alone. The machine name, which the scope shares, does not change. The README now
  says to give the role to each person who may use the app.

## Upgrade notes
Run `drush updb` and `drush cr`. Nothing else changes for existing sites.

## Demo kit (not part of the module package)
- The seed makes the `reviewer` an `owner` member of the demo apiary; since 3.0 access comes from the membership
  alone, and `assimilate` creates the apiary with no owner, so the reviewer would have seen no apiaries (task 0234).
- The kit's lock clears five security advisories: drupal/core 11.4.11, drupal/leaflet 10.4.13 and
  drupal/simple_oauth 6.1.3.
