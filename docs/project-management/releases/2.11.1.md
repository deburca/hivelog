# Release 2.11.1

A fix for the optional `assimilate` submodule (task 0213): its production guardrail now uses
the requirements hooks Drupal 11.3 and later run. Nothing changes unless you have enabled
`assimilate`, which is for development and demo sites only.

## Highlights
- **The guardrail would have vanished on Drupal 12.** From Drupal 11.3 a procedural
  `hook_requirements()` marked `#[LegacyRequirementsHook]` is skipped, and Drupal 12 removes the
  procedural hook. `assimilate` still had only the procedural function, so on Drupal 12 the check
  that refuses to install the demo module on a site with real AI-insight data, and the standing
  warning on the status report, would have stopped running **without any error**. It still worked
  on 11.4, with a deprecation notice.
- **Install time:** a class in `src/Install/Requirements/` now refuses the install, exactly as
  before: a real apiary with AI insights on blocks it; assimilate's own demo apiary and an apiary
  with insights off do not. Core loads it before the module is installed, so it is
  self-contained; and it tolerates the apiary type not existing yet when hivelog is installed in
  the same batch.
- **Status report:** an object-oriented `runtime_requirements` hook shows the standing reminder
  as a warning, and as an error once a real apiary has opted in later.
- The procedural function stays for Drupal before 11.3 (marked, and without the deprecated
  `REQUIREMENT_*` constants).
- The tests now drive the guardrail the way Drupal does (`drupal_check_module()` and the status
  report's list), not through the procedural function, which would have kept passing after Drupal
  stopped calling it. Without the new classes 3 of the 6 new tests fail.
- `AGENTS.md` records the convention for any submodule, so the same gap is not reintroduced.
