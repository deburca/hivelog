# Release 2.11.0

An addition to the optional `hivelog_api` submodule (task 0212): the app's writes now get
through a web host's firewall. Nothing changes unless you have enabled `hivelog_api`.

## Highlights
- **The problem.** Some shared hosts run a firewall that answers a bare `403` before Drupal
  sees a request, for any content type it does not know. On the live site that was
  JSON:API's own `application/vnd.api+json` (the type a write must use),
  `application/octet-stream` (a photo upload) and every `PATCH` and `PUT`. The field app could
  read and sign in but could record nothing, and the error it showed ("your account isn't
  allowed") pointed at the wrong thing.
- **On `/hivelog/api/v1`, a `POST` that carries an `Authorization` header may now be sent as
  `application/json`** (treated as `application/vnd.api+json`) **or, for a photo, as
  `multipart/form-data` with one file part** (treated as the raw upload JSON:API expects, with
  the part's file name). JSON:API then does everything it does today: validation, access,
  creating and attaching the file. Core reads an upload straight from `php://input`, which PHP
  leaves empty for a multipart body, so a small decorator on `file.input_stream_file_writer`
  hands core the uploaded file instead.
- **Narrow by design.** Only a `POST`; only with an `Authorization` header (a browser session
  gets nothing new: a form on another site can send `multipart/form-data` but cannot set that
  header); not the `computed/`, `schema` or `sign-out` routes; not plain `/jsonapi`. Up to
  10 MB per photo, a plain 400 or 413 otherwise.
- **The discovery document lists what the server accepts**:
  `meta.hivelog_api.features` is `["json_write", "multipart_upload"]`. An app uses the lenient
  types only when they are listed. `api_version` stays 1: this is additive.
- `PATCH` and `PUT` are not helped (the app does not use them). What a firewall does to the
  *content* of a request cannot be known until a real write is tried.

## Upgrade notes
- **Only affects a site that has enabled `hivelog_api`.** Core HiveLog is unchanged.
- Run `drush cr` after upgrading (a new subscriber, and a service decoration).
- A site whose host has such a firewall needs this release and an app build that uses it
  (the app asks the discovery document, so nothing needs configuring). If the host refuses even
  `application/json` and `multipart/form-data` writes to `/hivelog/api/`, ask the host to exempt
  that path.
