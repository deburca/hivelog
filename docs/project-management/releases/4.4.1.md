# Release 4.4.1

Adds one-off hive reminders (task 0274) and repairs the build that the first attempt at them broke. One new entity type,
one update hook (`hivelog_update_10041`), new permissions and routes. Covers every change on `main` since the 4.4.0 tag.

## Changes
- **One-off reminders for a single hive (task 0274).** A reminder has a hive, a due date, a short title, optional notes
  and a status (pending, done, dismissed). A **Reminders** section on the hive page lists the pending ones with an
  Overdue chip and an Add Reminder button (shown only to someone who may add one); Done and Dismiss open the reminder's
  edit form with that status already chosen, and nothing changes until it is saved. Reminders are listed under Hive
  reminders in the Apiaries menu, at `/hivelog/hive-reminders`.
- **Reminders appear in Needs attention.** Pending reminders on hives the user may see produce an alert: critical when
  overdue or due within three days, a warning when due within seven; a reminder further off shows no alert. The
  dashboard and the field app's `computed/alerts` read the same rows.
- **Access follows the apiary.** A reminder is read, edited and deleted by the apiary's owner or beekeeper (a novice reads
  only), and adding one needs `update` on the hive. Seven permissions are new: `view own`, `view any`, `add`, `edit own`,
  `edit any`, `delete own` and `delete any` hive reminder. `administer hivelog` bypasses them as elsewhere.
- **Repair: the reminders entity loads (PRs #224, #225).** `HiveReminder` was declared in the wrong namespace, so its
  class could not be autoloaded: kernel tests errored and `main`'s CI failed with "Cannot redeclare class". It now lives
  in `Drupal\hivelog\Entity` like every other entity. Dozens of workaround commits from that attempt (hand-built
  installers, per-test schema hacks, composer autoload edits, lint suppressions) are gone or were reverted.
- **Repair: the hive page no longer fails with a due reminder.** A reminder due today or earlier made the hive page return
  a 500 (an array literal passed to a renderer method that takes its argument by reference). Reminder titles are also
  escaped now, since the table prints its cells as raw HTML.
- **Calendar Actions page shows dates (task 0283, completed).** The collection page and its list builder now use the same
  date-range label as the other pages, under a "When" column header, for example "30 Mar – 3 May (W14–W18)".
- **Next visit on the inspection form (task 0274).** A new inspection offers an optional "Next visit" date and note; if
  filled in, it creates a reminder on that hive. Editing an inspection never creates one, a date before today is
  refused, and if the reminder cannot be created the inspection is still saved with a warning.
- **Deleting a hive deletes its reminders (task 0274).** Delete-dependency registry row `0274-1` (cascade), so no reminder
  is left pointing at a removed hive.
- **Code health (tasks 0290 to 0293).** Backslash escaping in translatable strings, `\Drupal::` calls in controllers and
  services replaced by injected dependencies, the reminder collection route, and test fixes that followed.

## Upgrade notes
- Run `drush updb`, then `drush cr`. `hivelog_update_10041` creates the hive reminder table on a site that already has the
  module; it is safe to run twice. A fresh install gets the table from core.
- No role is granted the new permissions. Give beekeepers `add hive reminder`, `view own hive reminder`, `edit own hive
  reminder` and `delete own hive reminder` at least, or they will see the section but not use it.
- The field app's allow-list and `hivelog_field_app` role are unchanged: reminders are web-only for now.
- A site that changed the service definition of `hivelog.breadcrumb` or subclassed a controller or service touched by
  task 0291 needs to check its constructor arguments (several gained injected dependencies).

## Known limitations
- Done and Dismiss are two clicks (open the form, save), not a one-click action.
- Reminders are web-only: the field app does not list or create them yet.

## Version note
This release adds an entity type, permissions and routes, which by the module's own convention is a minor release
(4.5.0). It is numbered 4.4.1 as requested. The `4.4.0` tag also carries `.info.yml` files that still read `4.3.0`
(corrected in this release), and `.github/scripts/check-release.sh` requires every `.info.yml`
to carry the tag, so the version bump must be part of this release's commit.
Release notes for 4.4.0 list task 0283 as shipped, but its Calendar Actions page change landed after the tag, in this
release.
