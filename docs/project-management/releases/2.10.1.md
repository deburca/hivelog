# Release 2.10.1

A fix for the optional `hivelog_api` submodule: its two entries on the status report
were missing on Drupal 11.3 and later. Nothing changes unless you have enabled
`hivelog_api`.

## Highlights
- **Fix: "HiveLog API: OAuth keys" and "HiveLog API: authorization-code scopes" never
  appeared on Reports > Status report** on Drupal 11.3 and later. From 11.3 Drupal skips
  a procedural `hook_requirements()` that is marked `#[LegacyRequirementsHook]` and
  expects an object-oriented hook in its place; the module had the marker but no
  replacement. The practical effect was that a missing or unreadable OAuth key pair, the
  one thing that stops the app from signing in, went unreported. The checks now run as a
  `runtime_requirements` hook (`Drupal\hivelog_api\Hook\HivelogApiRequirements`), and the
  procedural function delegates to it for older Drupal versions.
- The tests did not catch it because the old test called the procedural function
  directly. It is replaced by tests that read the requirements the way the status report
  does (through the system manager); they fail without the fix.

None.

## Upgrade notes
- **Only affects a site that has enabled `hivelog_api`.** Core HiveLog is unchanged.
- After upgrading, open Reports > Status report. "HiveLog API: OAuth keys" should say
  Configured, or Missing with the reason; if it says Missing, set the key paths at
  `/admin/config/people/simple_oauth` (keys outside the web root, readable by PHP).
- Run `drush cr` after upgrading (a new hook class).
- Drupal versions before 11.3 are unaffected: the procedural hook still runs there.
