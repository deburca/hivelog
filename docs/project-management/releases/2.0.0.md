# Release 2.0.0

## Highlights
- **Breaking: permission model change (task 0135).** `edit own api client`,
  `delete own api client`, `edit own ai provider config` and
  `delete own ai provider config` are removed — with create already
  administrator-only for both entity types, "own" mutate/delete access was
  reachable by no one, so the permissions were dead. A new
  `add sensor device` permission is added, scoped like `add hive`: it alone
  isn't enough, the contextual add routes also require `hive.update`/
  `apiary.update` on the target. **This is the reason for the major version
  bump** (ADR-0010: a permission-model change is a major bump).
- **Delete policy for records with children (ADR-0103, tasks 0134,
  0141–0145).** Every one of the 28 parent/child relationships in the module
  now has defined delete behaviour instead of none: 13 relationships **block**
  the parent's delete while children exist (task 0141), 9 **cascade**-delete
  owned records with their parent (task 0142), 3 **detach** an optional
  reference instead of blocking (task 0143), and 3 **warn** with links to the
  blocking children when neither block nor cascade fits (task 0144). A new
  `drush hivelog:orphans` command (task 0145) reports and can clean up
  orphaned records that predate this policy — **see Upgrade notes**.
- **One shared implementation per page kind (tasks 0125–0132).** Detail
  pages, list pages, delete forms and add/edit forms each now share one
  base/trait instead of 9–16 near-duplicate copies. Along the way: list
  pages gained proper pagination past the previous silent 50-row cutoff
  (task 0126), every add/edit form gained a Cancel link (task 0129), heading
  levels no longer skip H2→H3 (task 0128), and the full Hives / Inspections /
  Queen Observations list pages gained the same filters their embedded
  counterparts already had (task 0132).
- **Navigation consistency (tasks 0116–0123).** The breadcrumb builder is
  rebuilt around one parent-field map instead of ~10 near-identical ancestor
  walks (task 0116); every canonical page now owns its own Edit/Delete
  buttons and the old `hivelog.links.task.yml` / `hivelog.links.action.yml`
  local-task files are deleted (task 0118); the in-app nav strip and
  main-menu links now derive from one destination registry instead of three
  hand-synced lists (tasks 0119–0120); previously-unreachable collection
  pages (hive/apiary action logs) are now linked from the calendar sections
  that produce them (task 0121); Apiary and unassigned-Queen breadcrumbs
  thread through their own collection consistently with every other entity
  type (task 0122).
- **Housekeeping.** `nexus` now correctly depends on `hivelog:collective`
  instead of `collective:collective` and all four submodules track core's
  own version number going forward (task 0139); local lint/static-analysis
  now covers exactly what CI covers, including every submodule (task 0137);
  `AGENTS.md` is brought up to date with the module's real shape — 21 entity
  types and four submodules, not the 5/0 it previously described (task
  0138); five entity types that had a collection route but no
  `collection` link template now have one (task 0136); controller and form
  test gaps identified in the 2026-09-23 review are closed (task 0140).

## Upgrade notes
- **Breaking — permission model.** If any role on the target site was
  granted `edit own api client`, `delete own api client`,
  `edit own ai provider config` or `delete own ai provider config`, that
  grant is silently dropped on update (Drupal removes unknown permissions
  from roles automatically) — those actions were already unreachable in
  practice (create has always been administrator-only for both entity
  types), so no real access is lost. If any role should be able to add
  sensor devices, grant the new `add sensor device` permission explicitly —
  it is not enabled by default for any role.
- **Delete behaviour changes for existing sites.** 13 relationships that
  previously allowed a parent to be deleted out from under its children now
  **block** that delete with a dependency count and links to the blocking
  children instead. This can surprise a site that has grown used to being
  able to delete, e.g., a hive with inspections still attached.
- **Run `drush hivelog:orphans` after updating.** Sites that predate this
  release's delete policy can already have orphaned records the new BLOCK
  rules only prevent going forward — they don't retroactively fix existing
  gaps. `cms2` had 1,024 orphaned calendar actions and 9 orphaned inventory
  items at the time this was written. Run the command without arguments to
  report; consult its own `--help` for the cleanup option before running
  destructively.
- Any per-site menu-UI customisation of HiveLog's main-menu links (weight,
  enabled/disabled, expanded) is carried forward automatically by
  `hivelog_update_10029` — no manual re-configuration needed.
